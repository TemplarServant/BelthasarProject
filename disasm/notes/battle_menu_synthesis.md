## CORRECTION (2026-07-24) — `$0119` is the SCREEN BRIGHTNESS, not a music volume

Three claims in this dossier (and one in `menu_entry.md`) called `$0119` / DP `$19` a **music
volume**, and every "music fade" in the menu-entry, menu-exit, pause and game-over paths inherited
that label. It is wrong, and it matters now that the audio system is being built: wiring a volume
ramp to `$0119` would produce a mechanism the ROM does not have.

**`$0119` is the INIDISP brightness shadow.** The NMI handler writes it to `$2100` every frame,
substituting forced-blank when it is zero:

```
C0/EC4E  LDA $0119
C0/EC51  BNE ->EC55
C0/EC53  LDA #80        ; $0119 == 0  ->  forced blank
C0/EC55  STA $2100      ; INIDISP
```

Corroboration, all disassembled this pass:

- `C0/2824` ramps it **up**: `2829 INC $19 / ... / 283C LDA $19 / 283E CMP #0F / 2840 BMI ->2829`
  — a fade-IN that stops at 0x0F, which is INIDISP's maximum brightness (0-15), not a volume range.
- `C0/3AE7 LDA #0F / STA $19` (already correct in `field_op_e0_fadechange.md` §21, which calls it
  "the fade counter") arms the same 0x0F for the op-0xE0 location change.
- `C0/18E8` pause: `LDA $19 / STA $1A / LSR A / STA $19` — pausing **halves the screen brightness**
  (CT visibly dims on Start), restored by `190F LDA $1A / STA $19`.
- A ROM-wide scan finds exactly ONE `STA $2100` with `$19` loaded within the preceding 8 bytes:
  the `C0/EC55` above. No `$0119` path reaches the APU ports `$2140-43` at all.

The genuine audio surface is the `$2140-43` command channel and the SPC700's ARAM, observable with
the `--aram` oracle mode (`docs/DEBUG_SURFACE.md`).
