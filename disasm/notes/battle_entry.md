BATTLE-ENTRY DOSSIER — GATO, loc 006, from gato_press_action.state (+ --btnscript "100:8,0:N", A=0x100). Every claim below is cited to a ROM disassembly offset (tools/dis.py, file offset = bank-C0 CPU offset) or an observed oracle value (--monitor/--peek/--followvm via scratchpad/ct_probe.exe). The event-VM code runs with direct page D=$0100, so DP $17/$18/$1F in the disasm = WRAM $0117/$0118/$011F (proven: STZ $1F at C0/3AA8 produced the observed $011F write, writer PC C0:3AAA).

== 0. THE SCRIPT (scene 6 -> script 111, ct.py script 6) ==
GATO = obj8: fn0 `83 92 86` (op 0x83 LoadEnemy, ENEMY ID 0x92), `8B 08 08` coord (8,8), `0E 01`, `0D 02`; fn1 (activate) = `75 09` set loc[9]=1 only. The whole battle is driven by obj0's autorun continuation (body 0x0005-0x0099): a poll loop (`12 0A..`/`12 09 01..`/GOTO) that on loc[9]==1 runs: 0x15 `EA 00`, 0x17 `04 10 33` CALL obj8 fn3 (sing anim), 0x1A `EA 42` play song 0x42, 0x1C `BB 03` textbox str3, 0x1E `AD 20` wait, 0x20 `EA 00` song stop, 0x22 `E3 00` explore off, 0x24 `04 10 45` GATO pose, 0x29 `E7 00 02` screen scroll, 0x2C `D9 08 0B 8B 08 85 88` move party to battle spots, 0x33 `D8 92 20` = THE BATTLE OP, then 0x36+ post-battle: `16 EC 01 80 13` branch on $7F01EC, win/lose textboxes (BB 02 / BB 04), `E3 01` explore on, `75 0A` done-flag. IMPORTANT: in the saved state this sequence is ALREADY started — obj0 is parked on the `BB 03` textbox at f0 (followvm ip=0x13C) and with NO input nothing ever fires (400f monitor: $0117 stays 0); the scripted A press only DISMISSES the textbox.

== 2. THE MODE SWITCH ==
$0117 (event-DP $17) is the mainloop TRANSFER-REQUEST register: bit0=battle pending/in-progress, bit5=battle-intro trigger (both set by D8: `ORA #21 STA $17` C0/3AA4-3AA6); bit7=ChangeLocation request (adjacent handler C0/3AB7 = op-0xE0 family: loc->$0112, facing->$0116, `ORA #80`). $0118 bit0 = battle-DONE ack. The field frame tick polls it at C0/1770: `LDA $17 BIT #20` -> bit5 set -> TRB (C0/1779) -> intro path: $x38=1, JSR C0/885A, C0/00BF, EC60 frame-wait loop, C0/AF4E, JSL FD/FFF7 (vector -> FD/E39C), then a $0145-indexed intro-style switch (C0/179A-188B; styles 1-4 = DP-$1D00 camera/zoom variants; GATO ran style 0 — $0145 observed 0). Fallthrough C0/188C `BIT #01` -> bit0 -> C0/1890: JSR C0/024C; if it returns carry-set (no eligible enemy) -> C0/18CE immediate ack (TRB $17 / TSB $18 / BRL 00EB) = battle silently skipped; else JSL C1/0000 at C0/18A7. Return path C0/18AB-18CD: JSR C0/0B64+0B75, restore D=$0100 (C0/18B1-18B7), `TRB $17` bit0 (18B9) + `TSB $18` bit0 (18BD) = the ack the blocked D8 op waits on (C0/3A89: `LDA $18 BIT #01` -> TRB $18, IP+=3, C0/3AAD-3AB6), then JSR C0/0283 (result dispatch), C0/28E1, C0/E935, C0/00EB.

== 3. THE BATTLE-ENTRY ROUTINE CHAIN ==
Event-op dispatch table = C0/5D6E (entry=base+op*2; verified entries: D8->C0/3A83, D9->C0/326C, E0->C0/3AB7, E3->C0/3C05, E7->C0/3E30, EA->C0/3C2F, BB->C0/3570, 83->C0/46DF, 16->C0/63E6). C0/024C: JSR C0/0617 (enemy-list builder), on $9D>=0: JSR C0/038F + C0/0918, then records lead tile/facing $1801,Y/$1881,Y/$1600,Y (Y=$0197=lead idx*2) into $0102/03/04 (post-battle respawn cell). C0/0617 builder: arena origin $DB/$DD = $1D0A/2,$1D0E/2 (camera scroll), scans objects (count from $7F2000) requiring $1A81,X bit7 clear, $0F00,X!=0 (visible), $1100,X mode 5 or 6 (the two live-enemy modes; op-0x83 loads mode 5 which advances to 6 — oracle: GATO $1110=6), and on-screen (tileX-DB in 1..14, tileY-DD in 1..13); stores idx*2 into $019D,Y (cap 12, terminator 0x80). C0/038F = staging master: 039B (map-block stage around camera), 041A/0430 (PC stage), 04ED (enemy stage), 066D tail. Battle module entry C1/0000 = a JMP vector (entry0 -> C1/001B); battle init C1/8000 -> C1/8006 (JSL FD/A982, reads/masks $2989 at C1/801C-8029 — bit5 -> $B31F).

== 4. STAGED DATA (the field->battle interface = contiguous $7E29B0..$7E2A1F) ==
(a) PCs: C0/0430 writes 3x5 bytes at $7E29B0/29B5/29BA: relTileX(-$DB), relTileY(-$DD), fineX ($0A00,X&15), fineY ($0A80,X&15), prio ($0F01,X); plus per-PC cell prio override $0C00/01,X = ($2989&0x10)|0x20. (b) Enemies: C0/04ED clears 8 slots x 12 bytes at $7E29BF+12k then C0/0557 fills one per eligible object (the CANDIDATE LIST $019D..$01A2 = dp $9D..$A2, 6 entries, consumed by C0/052E-0551's six unrolled LDA/BMI/JSR pairs -- NOT the same array as the 8-entry SLOT back-map $01A3..$01AA it writes; slot 7 is legal): +0 relX, +1 relY, +2/+3 fine, +4 prio, +5 ENEMY ID = $1101,Y, +6 =0, +7 flags (($1201,Y&3)|($1A81,Y&0x80)|mode6?0x40), +8..+11 tail (C0/05F9+, semantics open). SLOT INDEX = f($0D00) (C0/0560: ((v>>4)-4)+((v>>3)&1)); against op-0x83's writer C0/47AC ($0D00 = ((slot&0xFE)<<4)|((slot&1)<<3), slot = (op2&0x7F)+1) that inverts EXACTLY to slotIndex = slot - 4 — GATO landed slot 3; oracle t2 wram: $29E3 = `08 06 08 0f 04 92 00 42 01 00 80 7f`). Slot valid iff +6 byte ($29C5+12k) bit7 clear (CC/EA62 BPL). (c) Flags: $7E2989 = D8 operand1 (GATO 0x92: bit4=PC-prio-front override C0/045A; bit5 -> C1/801C $B31F + C1/80F4 preset $AFAB..=1/$AFAE..=FF; bit2 read CC/F123; bits1,7 open), $7E2A1F = D8 operand2 (GATO 0x20: bit5 = scripted-loss-allowed/no-game-over — C0/0298: $7F01EC==1 && bit5 -> skip to 0304; also C0/1BFE music path; bit6 = battle-music variant — C0/1BB7: set -> sound cmd 0x70, clear -> cmd 0x14 via $1E00/$1E01 + JSL C7/0004). D8 operands across all 512 scenes are repeated flag patterns (12 00, 10 40, 92 C0...) — NOT formation ids: CT has NO formation table; the battle fights the on-screen enemy OBJECTS (op 0x83 `LoadEnemy`: handler C0/46DF stores mode 5 -> $1100,X, id -> $1101,X (C0/4557), enemy marker $1B01,X=1; oracle f0: $1110/$1111 = 06/92, $1B11=01). (d) Battle-side consumption: CC/EA33+ copies the staged block ($96B3 condensed, positions *16 -> $1D0C,Y/$1D23,Y, gfx from $E4:F600+id*10 and $E4:2300 packet table); FD/B2A9-B2D8 copies ids -> $AF02+Y/$AF0D+Y with Y = THE SLOT (INY every pass, no compaction: a slot-7 enemy lands at $AF02+7 -- oracle two-Diablos battle, $AF02[0..7] = FF 48 FF FF FF FF FF 48). $AEC6 is NOT the enemy count: FD/B2A3 zeroes it and FD/B2C9 `INC $AEC6` is the branch target of BOTH the empty (B2AC BMI) and hidden (B2BA BPL) tests, in a loop that always makes 8 passes (B2D8 CPX #0060) -- it is the SLOT COUNT, constant 8 (oracle $AEC5/$AEC6 = 03 08 with two enemies alive); FD/B438-B4D0 fetches ENEMY STATS from ROM $CC:4700 + id*23 (X=id*8*3-id at FD/B441-B44F) into $5FB0/1,Y(max) + $5FB2/3,Y(cur) etc., Y=slot*0x80, and there are EIGHT such blocks, not six: FD/B438 bounds nothing itself (Y comes straight from the slot) and C1/8357's enemy sweep runs `CPY #0400` = 0x400/0x80 = 8 passes. ## Key addresses
- $0117 (event DP $17) = mainloop transfer-request: bit0 battle pending, bit5 battle-intro trigger, bit7 changeloc (set by D8 at C0/3AA4)
- $0118 bit0 = battle-done ack (set C0/18BD, consumed by D8 handler C0/3A89->3AAD, IP+=3)
- $7E2989 = D8 operand1, battle flags A (bit4 PC-prio, bit5 -> $B31F)
- $7E2A1F = D8 operand2, battle flags B (bit5 scripted-loss-ok, bit6 music variant)
- $7E29B0-$7E29BE = staged PC block (3 x 5 bytes: relX,relY,fineX,fineY,prio) written C0/0430
- $7E29BF-$7E2A1E = staged enemy slots (8 x 12 bytes, id at +5, slot=f(screen pos)) written C0/04ED+C0/0557
- $019D-$01A8 = eligible enemy-object list (idx*2, 0x80 terminator) built by C0/0617
- $1100,X/$1101,X/$1B01,X = per-object mode(5->6=enemy)/enemy-id/enemy-marker (op-0x83 loader C0/46DF+C0/4557); GATO obj8: $1110=06,$1111=92,$1B11=01
- $AF02+/$AF0D+ = in-battle enemy id arrays (FD/B2AE); $AEFF-AF01 = battle party ids; $AEC6 count
- $5E32+slot*0x80 = battle actor HP blocks (GATO slot6: id $612D, HP $6132 = 76)
- $7F01EC = battle result (0 normal C1/81F9|C1/8357, 1 loss C1/813F; dispatch C0/0283/0289; script op-0x16 C0/63E6)
- $7E29AE = current-song shadow (op-EA C0/3C2F; battle-music start C0/1BAB, restore C0/1BE6 via $1E00 + JSL C7/0004)
- ROM C0/5D6E = event-op dispatch table (D8->C0/3A83, E0->C0/3AB7, E3->C0/3C05, EA->C0/3C2F, 83->C0/46DF)
- ROM C0/3A83 = op-0xD8 battle handler (blocking)
- ROM C0/1770-18CD = per-frame consumer: intro path C0/1779 (JSL FD/FFF7->FD/E39C, $0145 style switch), handoff C0/1890 (JSR C0/024C -> JSL C1/0000 at C0/18A7), skip-ack C0/18CE, return-ack C0/18B9-18C1
- ROM C1/0000 = battle module entry vector (->C1/001B); C1/8000->C1/8006 battle init
- ROM $CC:4700 + id*23 = enemy stats table (GATO id 0x92 -> $CC:541E, HP word 0x004C=76, oracle-byte-exact)
- ROM $E4:F600 + id*10 = enemy gfx table (shared by field op-0x83 and battle loader CC/EAD2+)
- $0102/$0103/$0104 = post-battle respawn cell+facing, re-recorded from lead at C0/026B-027A (writer C0:0277, observed (8,11) at f221)

## Open questions
- $2989 bits 1 and 7 (both set in GATO's 0x92) semantics unknown; bit2 reader CC/F123 (writes 0x40 markers to $7CFD,X) not decoded
- $2A1F bits other than 5/6 unknown (0xC0 is a common script pattern; readers CD/03B9-042B not decoded)
- $0145 battle-intro styles 1-4 (C0/17A0-1888 DP-$1D00 camera/zoom variants) unexercised by GATO (style 0) — which D8 flag or var selects them is unconfirmed ($0145 never written in our window)
- op-0x16 compare-mode jump table C0/6467 semantics not decoded, so which script branch (BB 02 vs BB 04) is win vs loss is unverified
- $7F01EC value 2 path (C0/0292->02CD, reads $2A1F) meaning unconfirmed (flee?)
- battle-END ack sequence ($0118 bit0 -> D8 IP+=3 -> script resume) is code-derived only: an idle battle never ends (GATO appears passive unprompted; $0117 stayed 0x01 through f10000), so no frame-level observation of the return path
- staged enemy record bytes +8..+11 (e.g. GATO `01 00 80 7f`, written by the C0/05F9 tail) not decoded
- the exact caller/frame-position of the C0/1770 poll inside the field frame tick was not traced (it sits after OAM-tail writes $09B4-$09B8)
- PC-stage byte order at $29B0 (Marle's record 0b 06 00 0f 02 vs D9 target (0B,08)) not field-by-field verified against C0/041A entry (only the 0430+ core was disassembled)
